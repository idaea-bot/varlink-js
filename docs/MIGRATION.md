# Migrating from varlink-js 0.1.x

varlink-js 1.0 is a rewrite. Nothing of the 0.1.x API is kept and there are no compatibility shims; this guide maps
the old names to the new ones. "0.1.x" means version 0.1.2, the last release (branch `master`). Its files are named
in git's `REV:PATH` form, e.g. `master:src/server/server.ts` (`git show master:src/server/server.ts` shows it); plain
paths are files of this tree.

Every "after" sample below is a copy of a file under [`examples/migration/`](../examples/migration/) that CI type-checks
and runs (`test/docs/examples.test.ts`, `test/docs/snippets.test.ts`). The "before" samples are 0.1.x code, shown for
comparison and not compiled.

## What changed, and why

| Area | 0.1.x | 1.0 | Why |
|---|---|---|---|
| Module format | CommonJS + ESM builds (tsup), no `exports` map; deep imports such as `varlink-js/client/client` | ESM only, an `exports` map with seven entry points (`varlink-js`, `varlink-js/node`, `/websocket`, `/http`, `/idl`, `/codegen`, `/testing`); deep imports are gone | The dual build loaded two copies of `VarlinkError`, so `instanceof` failed across them |
| Runtime | no `engines` field; tests ran on Bun | Node.js ≥ 22.12 (`require()` of ESM works there without a flag); Bun and Deno run the unit tests in CI | |
| Transports | `SocketClientSideTransport` / `SocketServerSideTransport` objects with Node `net` options | address strings: `unix:/path`, `unix:@name`, `tcp:host:port`, `exec:`, `ssh-unix:`, `ws://…`, … | One syntax shared with systemd and the other varlink implementations |
| Validation | none (`// TODO: Validate input.` in `master:src/server/server.ts`) | parameters are validated against the IDL before a handler runs; replies optionally | |
| Interface definitions | not parsed; hand-written method objects in `master:src/schemas/*.varlink.ts` | `varlink-js/idl` parses, validates and formats IDL; servers register IDL text | |
| Types | hand-written `VarlinkMethod` objects | generated by `varlink-js codegen` / `generate()` from the IDL | |
| `org.varlink.service` | implemented by hand on every server | built in: `GetInfo` lists the registered interfaces, `GetInterfaceDescription` returns their IDL | The 0.1.x reference server read `GetInterfaceDescription` answers from the file system, with a path traversal |
| Connections | `VarlinkClient` kept an implicit pool of sockets | a `Connection` is one socket (calls are pipelined); `createPool()` is an explicit pool | The implicit pool reused dead sockets and calls hung |

Fixes that change what you observe on the wire or in your code:

| Situation | 0.1.x | 1.0 |
|---|---|---|
| Oneway call | the method had to be registered with `registerCallOneshot`; a oneway call to another method got an error **reply**, which shifted every later reply by one | any method can be called oneway, and the server never writes anything for a oneway call, errors included |
| `more` on a method without streaming | error reply | one reply without `continues` (allowed by the spec); a method marked `[Requires 'more' flag]` answers `ExpectedMore` when called without `more` |
| Unknown method | `org.varlink.service.InvalidParameter` with the JS error text as `parameter` | `InterfaceNotFound`, `MethodNotFound` (`{method}`, fully qualified) or `MethodNotImplemented`, per the spec |
| Handler throws an `Error` | `InvalidParameter` carrying `e.toString()` (the message went to the client) | `io.github.pzmarzly.varlinkjs.InternalError` without details; the details go to the server's `onError` |
| Handler throws a non-`Error` (`throw "x"`) | no reply at all: the client hung | `InternalError` |
| `timeout` option | a socket idle timeout (`socket.setTimeout`); on the server an idle or slow client was destroyed with an exception that could end the process | a per-call client timeout (default 45 s; the clock starts when the call reaches the head of the reply queue); servers never drop idle connections |
| Where a TCP server listens | `new SocketServerSideTransport({ port })` listened on every interface (Node's default host) | `listen()` binds exactly what you pass: `tcp:127.0.0.1:12345` binds the loopback address only; the examples bind 127.0.0.1 |
| Address in use | an exception thrown from the server's `error` listener (uncaught) | `listen()` rejects with `EADDRINUSE` |
| Malformed input (`not json`, an unterminated 64 MiB message) | crashed the server / grew the buffer without bound | that connection is closed; messages are limited to 16 MiB |
| Final (non-error) replies | always carried `"continues": false` | default-valued fields are omitted |
| Integers beyond 2⁵³ | silently rounded by `JSON.parse` | rejected (`IntegerRangeError`) in the default `ints: "number"` mode, exact in `ints: "bigint"` mode |

## Old → new

| 0.1.x | 1.0 |
|---|---|
| `import { VarlinkClient } from "varlink-js/client/client"` | `import { connect } from "varlink-js/node"` |
| `import { SocketClientSideTransport } from "varlink-js/transport/node-socket"` | not needed: pass an address to `connect()` |
| `new SocketClientSideTransport({ host, port, timeout })` | `connect("tcp:HOST:PORT", { timeout })` (`timeout` is now per call) |
| `new SocketClientSideTransport({ path, timeout })` | `connect("unix:/path", { timeout })` |
| `new VarlinkClient(transport)`, `await client.connect()` | `const conn = await connect(address)` (connects at once) |
| `await client.disconnect()` | `await conn.close()` (or `await pool.close()`) |
| `client.call(method, input)` | `conn.call("iface.Method", parameters)`; typed: `X.client(conn).Method(parameters)` after codegen |
| `new VarlinkDynamicMethod("iface.Method")` (`varlink-js/protocol/protocol`) | the method name as a string |
| `client.callOneshot(method, input)` | `conn.oneway("iface.Method", parameters)` (resolves once written) |
| `client.callStream(method, input, async (error, data) => { … })` | `for await (const reply of conn.stream("iface.Method", parameters))`, or `await conn.collect(…)` |
| `OrgVarlinkService.GetInfo` / `.GetInterfaceDescription` (`varlink-js/schemas/org.varlink.service.varlink`) | `conn.getInfo()`, `conn.getInterfaceDescription(name)`; `conn.getInterface(name)` parses the IDL |
| `OrgVarlinkCertification`, `OrgVarlinkResolver` (`varlink-js/schemas/…`) | generate a module from the IDL (`varlink-js codegen`); resolver: `resolverResolve()`, `resolverGetInfo()` from `varlink-js/node` |
| `VarlinkMethod<Name, Input, Output>`, `VarlinkMethodGetInput<M>`, `VarlinkMethodGetOutput<M>` | generated descriptors and `<Method>_Input` / `<Method>_Output` types; `MethodInput<M>`, `MethodOutput<M>` |
| `import { VarlinkServer } from "varlink-js/server/server"` | `import { createServer } from "varlink-js"` |
| `new VarlinkServer(transport)` | `createServer({ vendor, product, version, url, onError })` |
| `server.registerCall(OrgVarlinkService.GetInfo, …)` | nothing: built in, from `createServer`'s options |
| `server.registerCall(method, fn)` | `server.addInterface(idlText, { Method: fn })`, or `server.implement(X, handlers)` after codegen |
| `server.registerCallOneshot(method, fn)` | the same handler; whether a call is oneway is the caller's choice (`ctx.oneway` tells) |
| `server.registerCallStream(method, async (input, callback) => …)` | an async generator handler (`yield` = reply with `continues`, `return` = final reply), or `ctx.notify(reply)` from a plain handler |
| `new SocketServerSideTransport({ port, host, timeout })` | `await listen("tcp:127.0.0.1:PORT")` (`timeout` is gone: no idle timeout) |
| `new SocketServerSideTransport({ path, timeout })` | `await listen("unix:/path", { mode: 0o644 })` |
| `await server.start()` | `server.serve(listener)` |
| `transport.address()` | `listener.address`, a varlink address string (`tcp:127.0.0.1:PORT` with the real port) |
| `await server.stop()` | `await server.shutdown()` (graceful, 5 s deadline; `{ graceful: false }` closes at once) |
| `VarlinkError` (`varlink-js/protocol/protocol`): `type_`, `parameters` | `VarlinkError` (`varlink-js`): `error`, `parameters`; subclasses for the standard errors; `isVarlinkError(e, name)` |
| `VarlinkClientSideTransport`, `VarlinkServerSideTransport`, `VarlinkTransportChannel` (`varlink-js/transport/transport`) | `ByteChannel` with `createConnection(channel)` and `server.handle(channel)`; a `Listener` for `server.serve()` |
| `serializeVarlinkRequest()` and the other wire helpers | internal, not exported |
| Connection pooling inside `VarlinkClient` | `createPool(address, { max, idleTimeout })` from `varlink-js/node` |
| `ReferenceServer` (`master:src/server/reference-server.ts`), `run-reference-server.ts` | certification: `examples/certification/server.ts`; a safe demo server: `examples/reference-server.ts` |
| Certification: `bun run test`, `PORT=12345 bun run test`, `PORT=12345 bun run ./src/server/run-reference-server.ts` | `node examples/certification/server.ts --varlink=…`, `node examples/certification/client.ts --varlink=…` (see [README](../README.md#certification)) |

## Client

Before (0.1.x README):

<!-- snippet: none (0.1.x, not compiled) -->
```typescript
import { VarlinkClient } from "varlink-js/client/client";
import { SocketClientSideTransport } from "varlink-js/transport/node-socket";

const transport = new SocketClientSideTransport({
  host: "127.0.0.1",
  port: 12345,
  timeout: 10_000,
});
const client = new VarlinkClient(transport);

// Call any method by name (no type safety)
import { VarlinkDynamicMethod } from "varlink-js/protocol/protocol";
const method = new VarlinkDynamicMethod("org.varlink.service.GetInterfaceDescription");
const response1 = await client.call(method, { interface: "org.varlink.service" });
console.log(response1.description); // any

// Or use type-safe wrappers
// (Currently NOT autogenerated)
import { OrgVarlinkService } from "varlink-js/schemas/org.varlink.service.varlink";
const response2 = await client.call(OrgVarlinkService.GetInterfaceDescription, { interface: "org.varlink.service" });
console.log(response2.description); // string
```

After:

<!-- snippet: examples/migration/client.ts -->
```ts
// MIGRATION.md "Client": `node examples/migration/client.ts ADDRESS` (e.g. against examples/reference-server.ts).
import { connect } from "varlink-js/node";

const address = process.argv[2] ?? "tcp:127.0.0.1:12345";
// `timeout` is now per call (default 45 s; 0 = none), not a socket idle timeout.
const conn = await connect(address, { timeout: 10_000 });
try {
  // Call any method by name: parameters and result are Record<string, unknown>.
  const response1 = await conn.call("org.varlink.service.GetInterfaceDescription", {
    interface: "org.varlink.service",
  });
  console.log(typeof response1.description); // string (unknown to TypeScript)

  // org.varlink.service has typed helpers; for your own interfaces, generate a typed client (examples/codegen).
  const description = await conn.getInterfaceDescription("org.varlink.service");
  console.log(description === response1.description); // true
} finally {
  await conn.close();
}
```

For typed calls to your own interfaces, see the codegen flow in the [README](../README.md#codegen) and
[`examples/codegen/`](../examples/codegen/).

## Server

Before (the 0.1.x README's server, plus the oneway and streaming registrations of `master:src/server/server.ts`):

<!-- snippet: none (0.1.x, not compiled) -->
```typescript
import { VarlinkServer } from "varlink-js/server/server";
import { SocketServerSideTransport } from "varlink-js/transport/node-socket";
import { OrgVarlinkService } from "varlink-js/schemas/org.varlink.service.varlink";
import { VarlinkMethod } from "varlink-js/protocol/protocol";

const Echo = new VarlinkMethod("org.example.migration.Echo", {} as { text: string }, {} as { text: string });
const Log = new VarlinkMethod("org.example.migration.Log", {} as { message: string }, {} as object);
const Ticks = new VarlinkMethod("org.example.migration.Ticks", {} as { count: number }, {} as { tick: number });

const transport = new SocketServerSideTransport({
  timeout: 10_000,
  port: 12345,
});
const server = new VarlinkServer(transport);
server.registerCall(OrgVarlinkService.GetInfo, async (_input) => ({
  vendor: "varlink-js",
  product: "varlink-js",
  version: "0.0.1",
  url: "https://example.com",
  interfaces: ["org.varlink.service"],
}));
server.registerCall(Echo, async (input) => ({ text: input.text }));
server.registerCallOneshot(Log, async (input) => {
  console.error(`log: ${input.message}`);
});
server.registerCallStream(Ticks, async (input, callback) => {
  for (let tick = 1; tick <= input.count; tick++) await callback({ tick }, tick < input.count);
});
await server.start();
console.log(transport.address());
```

After:

<!-- snippet: examples/migration/server.ts -->
```ts
// MIGRATION.md "Server": `node examples/migration/server.ts [ADDRESS]` (default tcp:127.0.0.1:12345).
import { createServer } from "varlink-js";
import { listen } from "varlink-js/node";

// GetInfo and GetInterfaceDescription (org.varlink.service) are built in: GetInfo lists the registered interfaces.
const server = createServer({
  vendor: "varlink-js",
  product: "varlink-js",
  version: "0.0.1",
  url: "https://example.com",
});

// Methods are declared in IDL; calls are validated against it before a handler runs.
const IDL = `interface org.example.migration

method Echo(text: string) -> (text: string)

method Log(message: string) -> ()

# [Requires 'more' flag]
method Ticks(count: int) -> (tick: int)
`;

server.addInterface(IDL, {
  // was registerCall
  Echo: (input: { text: string }) => ({ text: input.text }),
  // was registerCallOneshot: any handler can be called oneway; the server then sends no reply at all
  Log: (input: { message: string }) => {
    console.error(`log: ${input.message}`);
  },
  // was registerCallStream: ctx.notify() sends a reply with continues, the returned value is the final reply
  // (an async generator works too: yield = reply with continues, return = final reply)
  Ticks: async (input: { count: number }, ctx) => {
    for (let tick = 1; tick < input.count; tick++) await ctx.notify({ tick });
    return { tick: input.count };
  },
});

// The server binds exactly what you pass: 127.0.0.1 here, not every interface.
const listener = await listen(process.argv[2] ?? "tcp:127.0.0.1:12345");
server.serve(listener); // was server.start()
console.log(`Listening on ${listener.address}`); // was transport.address()

process.once("SIGTERM", () => {
  void server.shutdown().then(() => process.exit(0)); // was server.stop()
});
```

Notes:

- Handlers get `(parameters, ctx)`. `ctx.signal` aborts when the client disconnects or the server shuts down;
  `ctx.more` and `ctx.oneway` tell how the method was called.
- A handler may return a value, a promise, or an async iterator (streaming). Returning nothing sends `{}`.
- Interfaces can be added while serving. With codegen, `server.implement(X, handlers)` types the handlers from the IDL
  (see `examples/codegen/server.ts`).
- For a unix socket, pass a `mode` (`listen("unix:/run/x.sock", { mode: 0o644 })`); it is applied before the socket
  appears at its path.

## Errors

Before:

<!-- snippet: none (0.1.x, not compiled) -->
```typescript
import { VarlinkDynamicMethod, VarlinkError } from "varlink-js/protocol/protocol";

try {
  await client.call(new VarlinkDynamicMethod("org.example.reference.Lookup"), { word: "xyzzy" });
} catch (e) {
  if (e instanceof VarlinkError) console.log(e.type_, e.parameters);
}

// Server side: throw new VarlinkError("org.example.reference.NotFound", { word }) to send an error;
// any other Error was sent as org.varlink.service.InvalidParameter with e.toString() as the parameter.
```

After:

<!-- snippet: examples/migration/errors.ts -->
```ts
// MIGRATION.md "Errors": `node examples/migration/errors.ts ADDRESS` (against examples/reference-server.ts).
import { ConnectionClosedError, isVarlinkError, MethodNotFoundError, VarlinkError } from "varlink-js";
import { connect } from "varlink-js/node";

const address = process.argv[2] ?? "tcp:127.0.0.1:12345";
const conn = await connect(address);
try {
  // Error replies reject with a VarlinkError: `error` is the varlink error name (0.1.x: `type_`).
  try {
    await conn.call("org.example.reference.Lookup", { word: "xyzzy" });
  } catch (e) {
    if (!isVarlinkError(e, "org.example.reference.NotFound")) throw e;
    console.log(`${e.error} ${JSON.stringify(e.parameters)}`);
  }

  // Standard errors have classes. An unknown method is MethodNotFound (0.1.x sent InvalidParameter).
  try {
    await conn.call("org.example.reference.NoSuchMethod");
  } catch (e) {
    if (!MethodNotFoundError.is(e)) throw e;
    console.log(`${e.error} ${JSON.stringify(e.parameters)}`);
  }

  // Server side: throw a VarlinkError to send it; any other exception becomes
  // io.github.pzmarzly.varlinkjs.InternalError, and its details go only to the server's onError.
  console.log(new VarlinkError("org.example.reference.NotFound", { word: "xyzzy" }).message);
} finally {
  await conn.close();
}

// Local failures are not VarlinkErrors: ConnectionClosedError, CallTimeoutError, ProtocolError, ValidationError, …
try {
  await conn.call("org.example.reference.Ping", { ping: "too late" });
} catch (e) {
  if (!(e instanceof ConnectionClosedError)) throw e;
  console.log(`local error: ${e.name}`);
}
```

- A `VarlinkError`'s `message` is now just the error name (0.1.x: the name plus the JSON parameters).
- Prefer `isVarlinkError(e, name)` or a class's static `is(e)` over `instanceof`: they also work when two copies of
  the library are loaded.
- The full hierarchy, and how servers map exceptions to replies, is in the README's [Errors](../README.md#errors).

## Streaming

Before (as in 0.1.x's `master:src/client/client.test.ts`):

<!-- snippet: none (0.1.x, not compiled) -->
```typescript
const replies = [];
await client.callStream(
  new VarlinkDynamicMethod("org.example.reference.Count"),
  { n: 3 },
  async (error, data) => {
    if (error !== undefined) console.log("stream failed:", error.type_);
    else replies.push(data);
  },
);
```

After:

<!-- snippet: examples/migration/streaming.ts -->
```ts
// MIGRATION.md "Streaming": `node examples/migration/streaming.ts ADDRESS` (against examples/reference-server.ts).
import { isVarlinkError } from "varlink-js";
import { connect } from "varlink-js/node";

const address = process.argv[2] ?? "tcp:127.0.0.1:12345";
const conn = await connect(address);
try {
  // One iteration per reply, the final one included (0.1.x: one callback per reply).
  for await (const reply of conn.stream("org.example.reference.Count", { n: 3 })) {
    console.log(`reply ${String(reply.i)}`);
  }

  // An error reply is thrown by the loop (0.1.x passed it to the callback as its first argument).
  try {
    for await (const reply of conn.stream("org.example.reference.Count", { n: 0 })) console.log(reply);
  } catch (e) {
    if (!isVarlinkError(e, "org.example.reference.OutOfRange")) throw e;
    console.log(`stream failed: ${e.error}`);
  }

  // All replies at once (at most 1024 by default: the `max` option).
  const all = await conn.collect("org.example.reference.Count", { n: 3 });
  console.log(`collected ${String(all.length)} replies`);
} finally {
  await conn.close();
}
```

- The stream is pull-based: at most 64 unread replies are buffered (`highWaterMark`), then the connection stops
  reading, so a slow consumer slows the server down instead of filling memory.
- Leaving the loop early (`break`) before the final reply closes the connection: varlink has no way to cancel a call.
  Use a `Pool` if other calls must survive that.
- `timeout` applies only until the first reply of a stream; `idleTimeout` limits the gap between replies.

## Pool

0.1.x pooled implicitly: each `VarlinkClient` call took an idle socket or opened a new one, without a limit, and
put it back even after it had failed.

<!-- snippet: none (0.1.x, not compiled) -->
```typescript
const client = new VarlinkClient(transport);
const Ping = new VarlinkDynamicMethod("org.example.reference.Ping");
await Promise.all(["a", "b", "c", "d", "e", "f"].map((ping) => client.call(Ping, { ping }))); // six sockets
await client.disconnect();
```

After:

<!-- snippet: examples/migration/pool.ts -->
```ts
// MIGRATION.md "Pool": `node examples/migration/pool.ts ADDRESS` (against examples/reference-server.ts).
import { createPool } from "varlink-js/node";

const address = process.argv[2] ?? "tcp:127.0.0.1:12345";
// Each operation leases one connection until it settles; closed connections are dropped, never reused.
const pool = createPool(address, { max: 4, idleTimeout: 30_000 });
try {
  const words = ["a", "b", "c", "d", "e", "f"];
  const replies = await Promise.all(words.map((ping) => pool.call("org.example.reference.Ping", { ping })));
  console.log(replies.map((r) => r.pong).join(" ")); // a b c d e f
  console.log(`open connections: ${String(pool.size)}`); // at most 4
} finally {
  await pool.close();
}
```

- A pool has `call`, `oneway`, `stream`, `collect`, `getInfo`, `getInterfaceDescription`, `getInterface`,
  `addInterface` and `close` (no `proxy()`), and `X.client(pool)` works with generated code.
- Defaults: `max` 8 connections, `idleTimeout` 30 s, and an operation waits at most `timeout` (45 s) for a connection.
- A single `Connection` pipelines calls on one socket, which is often enough; use a pool for parallel, independently
  cancellable calls.

## Reference server and certification

The 0.1.x `ReferenceServer` (`master:src/server/reference-server.ts`) was the certification server; its
`GetInterfaceDescription` read `../schemas/${interface}.varlink` from disk, so a crafted interface name could read
other files. In 1.0:

- [`examples/certification/`](../examples/certification/) has the `org.varlink.certification` server and client, run
  against python-varlink and rust varlink in CI.
- [`examples/reference-server.ts`](../examples/reference-server.ts) is a small demo server: unix socket mode 0644 by
  default, TCP only on loopback, interface descriptions only from registered interfaces.

```sh
# 0.1.x: PORT=12345 bun run ./src/server/run-reference-server.ts
node examples/certification/server.ts --varlink=tcp:127.0.0.1:12345
python -m varlink.tests.test_certification --client --varlink=tcp:127.0.0.1:12345
```
